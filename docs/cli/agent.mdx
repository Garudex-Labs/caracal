Agents bundle MCP servers, skills, hooks, and prompts into one versioned registry object. References accept `namespace/slug`, UUIDs, unambiguous bare names, `@aliases`, and row numbers from the latest list.

| Command | Purpose |
| --- | --- |
| `list` / `show` | Browse and inspect |
| `pull` | Generate **and write** a complete harness installation |
| `init` / `add` / `build` / `publish` | Local YAML authoring workflow |
| `release` / `versions` | Version management |

Archiving, ownership transfer, and co-author management live in the web UI. All leaf commands support `--output table|json`. JSON mode never prompts: mutations need `--yes`, pull needs `--no-prompt`.

## list / show

```bash
caracal agent list --search 'incident response' --output json
caracal agent list --namespace richard --page 2 --limit 20
caracal agent show richard/reviewer --output json
```

`list` returns the paginated envelope and caches row numbers for later references. `show` returns the direct agent object with component links and success criteria.

## Local authoring: init → add → build → publish

```bash
caracal agent init --dir ./reviewer --name reviewer \
  --description 'Reviews changes' --prompt-file ./PROMPT.md \
  --model claude-sonnet-4 --harness kiro
caracal agent add skill 22222222-2222-2222-2222-222222222222 --dir ./reviewer
caracal agent build --dir ./reviewer
caracal agent publish --dir ./reviewer
```

- `init` writes `caracal-agent.yaml` atomically; refuses to overwrite.
- `add` accepts types `mcp`, `skill`, `hook`, `prompt`; duplicate type+UUID → exit 6.
- `build` validates composition, private-component visibility, and target scope. `publish` supports `--visibility project|private`.
- `publish` variants: `--draft` (save only), `--submit <ref>` (submit a draft), `--update --bump patch|minor|major` (update an existing agent). `--draft` and `--submit` are mutually exclusive; scope changes can't combine with `--update`.

The full workflow with context: [Build and publish an agent](/guides/build-agents).

## release / versions

```bash
caracal agent release richard/reviewer --bump patch --dir ./reviewer
caracal agent versions richard/reviewer --page 1 --page-size 50
```

`release` gets the server's version suggestion, submits the complete YAML snapshot, and updates local YAML only after the server accepts. Page size 1–100.

## pull

```bash
caracal agent pull <agent-ref> --harness <harness> [options]
```

| Option | Description |
| --- | --- |
| `--harness`, `-i` | Required target harness |
| `--dir`, `-d` | Project directory for generated paths |
| `--dry-run`, `-n` | Plan files and setup commands; write nothing, record nothing |
| `--scope` | `project` or `user` where the harness supports both |
| `--model` | Model ID or `harness=model`; repeatable |
| `--tools` | Claude Code tool allowlist |
| `--refresh-models` | Refresh the model catalog before an interactive picker |
| `--no-prompt`, `-y` | Disable all prompts (required with JSON output) |
| `--env`, `-e` / `--header`, `-H` | MCP env/header values as `NAME=VALUE`; repeatable |
| `--version`, `-V` | Exact semver agent version |
| `--output`, `-o` | Table or JSON |

Pull's sequence: validate options → resolve the agent and component requirements → check installed version conflicts → request harness config → validate every generated path → write/preview files and install skills → run required MCP registration commands → record versions in the lockfile → refresh the local layer snapshot.

Safety properties:

- Paths are confined to `--dir`; home paths only for explicit user scope. Traversal and symlink escapes are rejected.
- JSON sections merge; TOML managed tables replace idempotently; text files replace atomically. Unmergeable existing config → exit 6, untouched.
- Secrets travel only in the installation request and generated config - never in output, traces, or errors.
- Failed skill installs or MCP setup prevent lockfile recording; a lockfile write failure exits 9 rather than claiming success.
- No `OTEL_*` or telemetry env vars are generated.

JSON result shape:

```json
{
  "agent": { "qualified_name": "richard/reviewer", "version": "1.2.3", "local_name": "reviewer" },
  "harness": "kiro",
  "scope": "project",
  "dry_run": false,
  "target_directory": "/work/project",
  "files": [{ "path": "/work/project/.kiro/agents/reviewer.json", "status": "created" }],
  "warnings": [],
  "setup_commands": []
}
```

File statuses: `created`, `updated`, `merged`, `installed`, `cloned`, `would write`, `would clone`.

## Exit codes

Standard [CLI exit codes](/cli#exit-codes). Pull specifics: `6` unsafe config merge, `7` invalid harness/scope/version/path/option combination, `9` filesystem, lockfile, skill source, or setup command unavailable.
