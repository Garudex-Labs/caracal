---
title: "Environment variables"
description: "Server and CLI environment variables, defaults, and file-backed secret forms"
---

Server defaults live in `.env.example`; CLI defaults are built in. Runtime configuration beyond these boot values lives in dynamic settings - see [Configuration](/self-hosting/configuration).

<Info>
**File-backed secrets.** Every credential marked with file support accepts `NAME_FILE=/path/to/secret` instead of `NAME=value`. Files must be UTF-8, ≤ 64 KiB, optionally ending with one newline. Setting both forms is an error. The server-package installer writes generated credentials to operator-owned files under `secrets/`.
</Info>

## Server

### Core and security

| Variable | Default | Description |
| --- | --- | --- |
| `SECRET_KEY` | `change-me-to-a-random-string` | Application encryption secret, ≥ 32 random characters. `_FILE` supported |
| `OLD_SECRET_KEY` | unset | Previous secret during encrypted-setting rotation. `_FILE` supported |
| `FRONTEND_URL` | `http://localhost:8000` | External frontend URL (OAuth redirects, email links) |
| `CORS_ALLOWED_ORIGINS` | `http://localhost:8000` | Comma-separated allowed origins |
| `MAX_REQUEST_SIZE_MB` | `10` | Maximum request body size |
| `RATE_LIMIT_AUTH` | `10/minute` | General auth-endpoint rate limit |
| `RATE_LIMIT_AUTH_STRICT` | `5/minute` | Login and password-reset rate limit |

### Databases

| Variable | Default | Description |
| --- | --- | --- |
| `DATABASE_URL` | `postgresql+asyncpg://postgres:postgres@localhost:5432/caracal` | PostgreSQL; also the source URL for `server migrate`. `_FILE` supported |
| `POSTGRES_USER` / `POSTGRES_PASSWORD` | `postgres` / container-specific | Postgres container credentials; `POSTGRES_PASSWORD_FILE` supported |
| `CLICKHOUSE_URL` | `clickhouse://localhost:8123/caracal` | ClickHouse; also `server migrate` source. `_FILE` supported |
| `CLICKHOUSE_USER` / `CLICKHOUSE_PASSWORD` | `default` / container-specific | ClickHouse credentials |
| `TARGET_DATABASE_URL` / `TARGET_CLICKHOUSE_URL` | unset | Targets for `server migrate` import/validate |
| `REDIS_URL` | `redis://localhost:6379` | Redis connection. `_FILE` supported |
| `DATA_RETENTION_DAYS` | `90` | ClickHouse TTL in days; `0` disables; minimum non-zero `7` |

### JWT signing

| Variable | Default | Description |
| --- | --- | --- |
| `JWT_SIGNING_ALGORITHM` | `ES256` | `ES256` or `RS256` |
| `JWT_KEY_DIR` | `~/.caracal/keys` (host) / `/data/keys` (Docker) | Generated signing keys. **Back this up** - losing it invalidates every session |
| `JWT_KEY_PASSWORD` | unset | Optional private-key encryption password. `_FILE` supported |

### SSO

OIDC, SAML, and SSO-only mode are configured in **Admin → SSO** and stored as dynamic settings; OIDC client changes require an API restart. Legacy direct `OAUTH_*`, `SSO_ONLY`, and `SAML_*` env values are imported once when the matching database setting is empty. File-backed forms (`OAUTH_CLIENT_SECRET_FILE`, `GOOGLE_OAUTH_CLIENT_SECRET_FILE`, `GITHUB_OAUTH_CLIENT_SECRET_FILE`, `INSIGHTS_API_KEY_FILE`, `SAML_IDP_X509_CERT_FILE`, `SAML_SP_KEY_ENCRYPTION_PASSWORD_FILE`) stay in memory and are never imported into the database. `SAML_SP_PRIVATE_KEY_FILE` and `SAML_SP_X509_CERT_FILE` must be set together and override generated SP material. See [SSO](/self-hosting/sso).

### Git operations (submission analysis)

| Variable | Default | Description |
| --- | --- | --- |
| `ALLOW_INTERNAL_URLS` | `false` | Allow internal/private git URLs (GitLab / GHE) |
| `GIT_CLONE_TOKEN` | unset | Token for private repos. `_FILE` supported |
| `GIT_CLONE_TOKEN_USER` | `x-access-token` | Token username: `x-access-token` (GitHub), `oauth2`/`private-token` (GitLab) |
| `GIT_CLONE_TIMEOUT` | `120` | Clone timeout, seconds |

### AWS (Bedrock, legacy only)

Bedrock supports API keys - use one like any other insights provider key. `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`, and `AWS_REGION_NAME` (default `us-east-1`) exist only for legacy instance-role/task-role setups where the insights LLM client auto-discovers credentials.

### Development-only login

| Variable | Default | Description |
| --- | --- | --- |
| `AUTH_NODE_ENV` | `production` | `NODE_ENV` for the identity service container |
| `AUTH_DEV_LOGIN` | `0` | Enable the development login route (`1`) |

<Warning>
The identity service registers the development login route only when **both** conditions hold: `NODE_ENV` is not `production` and `AUTH_DEV_LOGIN=1`. A production `NODE_ENV` disables it regardless of `AUTH_DEV_LOGIN`. Never set these in a real deployment.
</Warning>

### Identity sessions

| Variable | Default | Description |
| --- | --- | --- |
| `AUTH_SESSION_HISTORY_RETENTION_DAYS` | `30` | Days of ended/renewed authentication sessions kept in a device's history on the account security page. Active sessions are always shown; integer 1-365 |

Compose-only. Prometheus/Grafana ports apply only with the observability overlay.

| Variable | Default | Service |
| --- | --- | --- |
| `CARACAL_BIND_ADDRESS` | `127.0.0.1` (server package) | Host address for published ports - a non-loopback value is explicit remote exposure |
| `CARACAL_SECRET_GID` | operator group from setup | Container group allowed to read `0640` secret files |
| `API_HOST_PORT` | `8080` | API (behind the LB) |
| `WEB_HOST_PORT` | `3000` | Web UI |
| `POSTGRES_HOST_PORT` | `5432` | PostgreSQL |
| `CLICKHOUSE_HOST_PORT` | `8123` | ClickHouse |
| `REDIS_HOST_PORT` | `6379` | Redis |
| `PROMETHEUS_HOST_PORT` | `9090` | Prometheus (optional) |
| `GRAFANA_HOST_PORT` | `8002` | Grafana (optional) |

### Grafana (optional overlay)

`GRAFANA_ADMIN_USER` (default `admin`), `GRAFANA_ADMIN_PASSWORD` (+ `_FILE`), and `GRAFANA_CLICKHOUSE_PASSWORD_FILE` (datasource password mounted only into Grafana).

## CLI

Read at invocation time; they override `~/.caracal/config.json` for that invocation.

| Variable | Default | Description |
| --- | --- | --- |
| `CARACAL_SERVER_URL` | from config | Server URL |
| `CARACAL_ACCESS_TOKEN` | from config | Access token (preferred name for CI) |
| `CARACAL_TOKEN` | - | Legacy CI alias with highest precedence |
| `CARACAL_PASSWORD` | unset | Credential or bootstrap login password |
| `CARACAL_CURRENT_PASSWORD` / `CARACAL_NEW_PASSWORD` | unset | Non-interactive password changes |
| `CARACAL_TIMEOUT` | `30` | HTTP timeout, seconds |

Token and password variables support `_FILE` forms; setting both a direct value and its file form is an error. Alias precedence: `CARACAL_TOKEN` > `CARACAL_ACCESS_TOKEN`.

```bash
export CARACAL_SERVER_URL=https://caracal.your-company.internal
export CARACAL_ACCESS_TOKEN_FILE=/run/secrets/caracal-token
caracal ops traces --limit 100 --output json | jq
```
